# MFP — Google-style UX/UI Skill

Skill นี้ใช้ออกแบบ frontend ของ **MFP — Merchant Financial Passport** (React + Vite + TypeScript + Recharts)
ให้มีอารมณ์แบบ Google: **สะอาด เรียบ ตรงไปตรงมา เข้าใจได้ในไม่กี่วินาที** อิงหลัก Material Design 3 (M3)

ผู้ใช้หลักคือ **เจ้าของร้านค้าขนาดเล็ก** ไม่ใช่นักการเงินหรือนักวิเคราะห์ข้อมูล
ทุกการตัดสินใจด้านดีไซน์ให้ถามว่า "เจ้าของร้านเปิดหน้านี้แล้วรู้ไหมว่า **ต้องทำอะไร และเมื่อไหร่**"

> อ่านคู่กับ `CLAUDE.md` และ `docs/frontend/requirements.md` — กฎในสองไฟล์นั้น **มีลำดับความสำคัญสูงกว่า** skill นี้เสมอ

## 1. หลักการออกแบบ 6 ข้อ (Google mindset)

| # | หลักการ | ใน MFP หมายถึง |
| --- | --- | --- |
| 1 | **คำตอบมาก่อน รายละเอียดตามมา** | บนสุดของ Passport คือประโยคเดียวบอกสถานะร้าน เช่น "อีก 5 วัน (22 ก.ค. 2558) เงินสดอาจไม่พอ ประมาณ 7,945" |
| 2 | **หนึ่งหน้าจอ หนึ่งงานหลัก** | ปุ่มหลัก (Filled button) มีได้ไม่เกิน 1 ปุ่มต่อส่วน |
| 3 | **ค่อย ๆ เปิดเผย (progressive disclosure)** | ค่าเริ่มต้นแสดงแบบง่าย ที่เหลือซ่อนหลัง "แสดงรายละเอียด" / expand |
| 4 | **พื้นที่ว่างคือเพื่อน** | ระยะห่างตาม grid 8dp, การ์ดไม่อัดข้อมูลเกิน 3 ตัวเลขสำคัญ |
| 5 | **สีมีความหมาย ไม่ใช่ของตกแต่ง** | ฟ้า = ข้อมูล/การกระทำ, เขียว = ปกติ, เหลืองอำพัน = ระวัง, แดง = เงินขาด — และต้องมีไอคอน/ข้อความกำกับเสมอ |
| 6 | **ซื่อตรงกับข้อมูล** | ข้อมูลจำลองติด badge ทุกจุด, สัญญาณการเงินเขียน "ทดลอง" เสมอ (ดูข้อ 7) |

## 2. Design tokens (Material 3 แบบ light-first)

`index.css` เป็น light-first แล้ว และมี dark theme เป็นตัวเลือก (`data-theme="dark"`) ค่าจริงอยู่ในไฟล์นั้น ตารางนี้เป็นค่าตั้งต้น
ข้อความบนพื้น `--*-soft` ให้ใช้ `--on-*-soft` เพราะค่า `--bad`, `--good`, `--warn` บนพื้นอ่อนได้ contrast ไม่ถึง 4.5:1

### 2.1 สี

### 2.2 ตัวอักษร

```css

font-variant-numeric: tabular-nums; /* ตัวเลขเงินเรียงตรงกัน */
```
(โหลด Roboto + Noto Sans Thai จาก Google Fonts; ภาษาไทยให้ line-height ≥ 1.5)

| Role (M3) | ขนาด/น้ำหนัก | ใช้กับ |
| --- | --- | --- |
| Display S | 36 / 400 | ตัวเลขใหญ่ในการ์ดสรุป |
| Headline S | 24 / 400 | ชื่อหน้า, ชื่อร้าน |
| Title M | 16 / 500 | หัวการ์ด |
| Body L | 16 / 400 | ประโยคสรุป, คำตอบ copilot |
| Body M | 14 / 400 | ข้อความทั่วไป, ตาราง |
| Label M | 12 / 500 | badge, chip, แกนกราฟ |

### 2.3 รูปทรง ระยะ และเงา

- Spacing: 4 / 8 / 12 / 16 / 24 / 32 / 48 (grid 8dp)
- Corner radius: chip/badge 8px · การ์ด 16px · ปุ่ม/ช่องค้นหา 9999px (pill) · dialog 28px
- Elevation: การ์ดใช้ **เส้นขอบ 1px แทนเงา** (Outlined card) — เงาใช้เฉพาะ app bar ตอน scroll และ menu/dialog
- Icon: Material Symbols Rounded ขนาด 20/24 ผ่าน `<Icon>` ใน `ui.tsx` — ไฟล์ฟอนต์เป็น subset ใน `public/fonts/` รายชื่อและวิธีเพิ่มอยู่ใน `frontend/README.md`

### 2.4 Motion

- ระยะเวลา 150–300ms, easing `cubic-bezier(0.2, 0, 0, 1)` (M3 emphasized)
- เคารพ `prefers-reduced-motion` (มี `prefersReducedMotion()` ใน `theme.ts` แล้ว)
- ฉาก 3D (`components/three/*`) เป็น **ของเสริม** ปิดเป็นค่าเริ่มต้น และไม่วางไว้เหนือข้อมูลสำคัญ — label ใช้ `three/Label.tsx` ห้ามใช้ drei `<Html>`

รายละเอียดแต่ละส่วน:

**A. Status banner** — ส่วนสำคัญที่สุด (หลัก "คำตอบมาก่อน")
- มี gap → พื้น `--bad-soft`, ไอคอน `warning`, ต้องมี **วันที่ + จำนวนเงิน** เสมอ
- ไม่มี gap → พื้น `--good-soft`, ไอคอน `check_circle`, "ไม่พบช่วงที่เงินสดอาจไม่พอใน 14 วันข้างหน้า"
- ปุ่ม "ดูรายละเอียด" เลื่อนไปที่การ์ด E

**B. Summary cards** — 3 ใบ, ตัวเลขใหญ่ (Display S) หนึ่งตัวต่อใบ, ใต้ตัวเลขมีบรรทัดอธิบายสั้น ๆ
- บนมือถือให้เลื่อนแนวนอน (carousel) หรือเรียงลงมา — ห้ามมี horizontal scroll ทั้งหน้า

**C. การนำทางภายในหน้า** — Tabs แบบ M3 (Primary tabs) ติดบนเมื่อ scroll (sticky) ช่วยให้หน้ายาวไม่หลง

**D. กราฟยอดขาย** — ใช้ Segmented button สำหรับช่วงเวลา (state เดียวกับกราฟยอดเงิน), ปุ่ม ⓘ เปิด bottom sheet/dialog อธิบายวิธีอ่านกราฟเป็นภาษาง่าย ๆ (ดูข้อ 6)

**E. การ์ดเตือน** — หัวการ์ด "วันที่ 22 ก.ค. 2558 เงินสดอาจไม่พอ ขาดประมาณ 7,945" แล้วตามด้วยรายการ contributors แบบ list (label · วันครบกำหนด · จำนวน) ชิดขวา, ตัวเลข tabular

**G. ปัจจัย** — 2 คอลัมน์ (มือถือ = ซ้อนกัน) แต่ละข้อเป็น list item มีไอคอน; องค์ประกอบ 5 ตัวแสดงเป็น Linear progress indicator พร้อม % น้ำหนัก

**H. AI Copilot** — สไตล์ Gemini/Google Assistant: ปุ่มลอยมุมขวาล่าง เปิดเป็นหน้าต่างแชตแบบไม่ modal (มือถือเต็มจอ) ไม่มีแท็บในหน้า
- Suggestion chips ก่อนพิมพ์: "สรุปสถานะร้าน", "สัปดาห์หน้าต้องระวังอะไร"
- ช่องพิมพ์แบบ pill + ปุ่มส่ง (ไอคอน `send`) ปิดการกดระหว่างรอ
- Loading: 3 จุดเคลื่อนไหว + "กำลังสรุปข้อมูล…" (อาจนานถึง ~40 วินาที → หลัง 8 วินาทีเปลี่ยนข้อความเป็น "ใช้เวลานานกว่าปกติเล็กน้อย")
- คำตอบใช้ `white-space: pre-line`, badge "AI (Typhoon)" หรือ "สรุปอัตโนมัติ", disclaimer ใต้คำตอบเสมอ, **ไม่แสดง `fallback_reason`**

**I. ข้อเสนอ** — Outlined card + badge "ตัวอย่าง" + ข้อความ "ข้อเสนอจำลอง ไม่ใช่ข้อเสนอจริงจากผู้ให้บริการ"; ปุ่มเป็น Text button "ดูข้อมูลเพิ่มเติม" ไม่ใช่ Filled button (ไม่ชักชวนเกินจริง)

### หน้า 3 — ผลโมเดล (`/model-results`)

หน้านี้สำหรับผู้นำเสนอ/อาจารย์ — ใช้ศัพท์เทคนิคได้
- Segmented button: Test (ค่าเริ่มต้น) | Validation
- Data table แบบ M3: หัวตาราง Label M, ตัวเลขชิดขวา, แถว **LSTM+GRU (โมเดลหลัก)** ไฮไลต์พื้น `--accent-soft` + chip "โมเดลหลัก"
- กราฟแท่ง WAPE แนวนอน + เส้นอ้างอิง "เป้า WAPE ≤ 20%"
- ข้อความสรุปใต้ตารางตาม requirements.md

## 6. กราฟ (Recharts) แบบ Google

- พื้นกราฟเรียบ, เส้น grid แนวนอนอย่างเดียว สี `--border` บาง ๆ, ไม่มีกรอบรอบกราฟ
- แกน Label M สี `--text-3`, ตัวเลขย่อ (เช่น 12k) บนแกน แต่ tooltip แสดงเต็ม

| ข้อมูล | รูปแบบ |
| --- | --- |
| ยอดขายจริง | เส้นทึบ 2px `--accent` |
| คาดการณ์ | เส้นประ 2px `--accent` |
| ช่วงคาดการณ์ | พื้นที่ `--accent-soft` ป้าย "ช่วงคาดการณ์โดยประมาณ" (ห้ามเขียน "มั่นใจ 80%") |
| วันนี้ (17 ก.ค.) | เส้นแนวตั้ง `--text-3` + ป้าย "วันนี้" |
| วันที่เงินอาจขาด | จุด/เส้น `--bad` + ไอคอน |
| โมเดลทายไว้ล่วงหน้า | เส้นสีส้ม `--warn` (อยู่ในส่วน "แม่นแค่ไหน") |
| ยอดขายจำลอง | เส้นเทาจุดขีด ป้าย "ยอดขายจำลอง (ไม่ใช่ข้อมูลจริง)" |
| ยอดเงินติดลบ | เส้น 0 สี `--bad`, จุดแดงวันที่ติดลบ |

- Legend อยู่**ด้านบน**กราฟ ชิดซ้าย เป็น chip เล็ก กดซ่อน/แสดงซีรีส์ได้
- Tooltip เป็นการ์ดลอยพื้น `--surface` มีเงา: วันในสัปดาห์ + วันที่ พ.ศ. → ค่าต่าง ๆ
- วันร้านปิด: เว้นช่องว่าง (`connectNulls={false}`) ไม่ลากลงศูนย์
- มีทางเลือก "ดูเป็นตาราง" (`ViewToggle`) เพื่อการเข้าถึง
- ประโยคสรุปเหนือกราฟทุกครั้ง — กราฟคือหลักฐาน ประโยคคือคำตอบ

## 9. Accessibility & Responsive

- Touch target ≥ 48×48px, focus ring ชัด (`outline: 2px solid var(--accent)`, offset 2px)
- ทุกไอคอนที่ไม่มีข้อความต้องมี `aria-label`; badge สถานะต้องอ่านออกด้วย screen reader
- `lang="th"`, ใช้ heading ตามลำดับ (h1 ชื่อร้าน → h2 แต่ละส่วน)
- กราฟมี `role="img"` + `aria-label` ที่เป็นประโยคสรุป
- 375px: ไม่มี horizontal scroll, ตารางยาวให้เลื่อนในกรอบตัวเอง, การ์ดสรุปซ้อนกัน
- รองรับ `prefers-color-scheme` และ `prefers-reduced-motion`
